# 지도 탭 마커 표시 개수 제한 적용

## Context and Problem Statement

지도 탭은 필터에 맞는 매물을 전부 마커로 만듦.
마커 1개마다 라벨 + 핀 PNG를 2장(선택 / 기본) 그려 지도에 올리기 때문에
매물이 늘어날수록 지도 탭 첫 화면이 늦게 뜨고 메모리 사용량이 커지는 문제가 있음

## Decision Drivers

* 지도 탭 첫 화면에 마커가 보일 때까지 걸리는 시간
* 메모리 사용량
* 매물이 한 지역에 몰려 있어도 효과가 있을 것

## Considered Options

* 지금처럼 필터에 맞는 매물 전체 표시
* 화면 범위 근처 + zoom별 최대 개수

## Decision Outcome

선택: "화면 범위 근처 + zoom별 최대 개수"
사유: 매물이 흩어져 있든 한곳에 몰려 있든 첫 화면 마커 표시 시간과 메모리가 함께 줄어들기 때문

- 카메라가 멈출 때마다 화면 범위를 상하좌우 50% 넓힌 영역 안의 매물만 고름
- 그중 zoom별 최대 개수를 넘으면 카메라 중심과 가까운 순 → 금액 가까운 순(기존 목록 정렬)으로 남김

| zoom | 최대 개수 |
|---|---|
| 10 미만 | 10 |
| 10 이상 13 미만 | 15 |
| 13 이상 15 미만 | 20 |
| 15 이상 | 제한 없음 (범위 안 전부) |

- 선택한 매물은 범위·최대 개수와 상관없이 마커를 유지
- `lib/features/map/map_vm.dart`의 `_markers`·`_maxMarkerCount`·`_limit`에서 마커 목록을 정하고, `lib/components/widgets/map/native_map_state.dart`의 `_onStopCamera`가 카메라 중심·zoom·화면 범위를 `NativeMap.onStopCamera`로 VM에 전달
- `native_map_state.dart`의 `_updateMarkers`는 이미 그린 마커를 다시 쓰고 새로 들어온 마커만 그리도록 변경 (카메라가 멈출 때마다 전부 다시 그리지 않게)

### Consequences

* 장점: 지도 탭 첫 화면의 마커 표시 시간 약 2.1~2.7초 → 0.4~0.8초
* 장점: 메모리 감소 (밀집 데이터 약 64~84MB, 분산 데이터는 100개가 한 화면에 보이던 zoom 9에서 약 91MB)
* 단점: 축소한 상태에서는 일부 매물이 지도에 보이지 않음
* 단점: 카메라가 멈출 때마다 마커 목록을 다시 계산함
* 단점: 위치 권한이 없을 때 매물 구성이 바뀌면 전체 마커를 올려 카메라를 맞춘 뒤 다시 줄임

### Confirmation

#### 밀집 데이터 (서울시청 반경 1km, 매물 100개)
- 환경: iPhone 17 Pro 시뮬레이터(iOS 26.2), 디버그 빌드, 현재 위치 서울시청 고정, 위치 권한 허용
- 버전: 이전 버전(`main`) / 바꾼 버전(커밋 `a660768`, 지도 첫 진입 크래시 수정 포함)
- 방법: 앱을 완전히 종료 → 재시작 → 지도 탭 진입(내 위치 기준 zoom 14) → 3초 뒤 서울시청 중심 zoom 9 / 12 / 14 / 16으로 카메라 이동
  - 마커 그리는 시간: `_updateMarkers` 시작 → `addOverlayAll` 완료. 첫 화면은 zoom 이동 전까지의 갱신 시간 합

- 값은 3회 평균, 괄호는 회차별 값

- 결과
  - 이전 버전은 zoom과 상관없이 첫 화면에서 100개를 모두 그려 약 2.1~2.7초가 걸림
  - 바꾼 버전은 첫 화면에서 최대 20개만 그려 평균 0.4~0.8초로 줄어듦
  - 메모리는 처음에 그린 마커 개수를 따라감. 밀집 데이터는 모든 zoom에서 약 64~84MB, 분산 데이터는 이전 버전에서 100개가 한 화면에 다 보이던 zoom 9에서 약 91MB 줄어듦
  - 분산 데이터 zoom 12~16의 메모리 차이(−9~−17MB)는 회차별 흔들림(약 ±15MB)과 비슷해 차이가 있다고 보기 어려움
  - 이미 그린 마커를 다시 쓰기 때문에 zoom을 바꿀 때 줄이기만 하는 경우는 10~26ms, 새로 그려야 하는 경우는 그린 개수만큼(1개당 약 15~20ms) 걸림
  - 첫 화면에서 지도의 기본 zoom(11) 기준으로 15개를 먼저 그리고 내 위치(zoom 14)로 이동한 뒤 다시 맞추는 회차가 있어 첫 화면 시간이 회차마다 0.2~0.9초로 흔들림
  - 이전 버전·바꾼 버전을 합쳐 앱 실행 66회(재측정 포함) 동안 크래시 없음
  - 3회씩의 테스트라 모수가 적음

## Pros and Cons of the Options

### 지금처럼 필터에 맞는 매물 전체 표시

* 장점: 어느 zoom에서든 모든 매물을 지도에서 볼 수 있음
* 단점: 매물 수만큼 마커를 그려 첫 화면이 늦게 뜨고 메모리를 많이 씀
  - 화면 밖 매물까지 그리기 때문에 확대한 상태에서도 비용이 그대로임

### 화면 범위 근처 + zoom별 최대 개수

* 장점: 매물이 흩어져 있든 몰려 있든 그리는 개수가 최대 20개(zoom 15 미만)를 넘지 않음
* 장점: 화면 범위를 50% 넓혀 두어 지도를 조금 움직여도 마커가 바로 보임
* 단점: 축소한 상태에서는 가까운 순으로 잘린 매물이 보이지 않음
  - 매물 목록 탭에서 전체를 볼 수 있고, 확대하면 다시 보이므로 지도에서는 가까운 매물 위주로 보여주는 것이 맞다고 판단함

## More Information

- 코드 위치: `lib/features/map/map_vm.dart`의 `_markers`·`_maxMarkerCount`·`_limit`, `lib/components/widgets/map/native_map_state.dart`의 `_onStopCamera`·`_updateMarkers`
- 시뮬레이터 디버그 빌드 수치라 실기기 릴리즈 빌드와 다를 수 있음.
- 측정 중 지도 첫 진입 때 내 위치 아이콘 이미지를 설정하다 앱이 죽는 문제가 있었음 (flutter_naver_map 1.4.4 임시 폴더 초기화 경쟁 조건). 앱 시작 때 내 위치 아이콘을 미리 저장하고(`main.dart`의 `NativeMap.prepareImages` → `AppManager.shared.mapImagesReady`), 지도는 `NativeMap.onInit`으로 그 준비가 끝난 뒤 이미지를 만들도록 수정했고, Confirmation의 바꾼 버전 수치는 모두 수정한 코드로 측정함
