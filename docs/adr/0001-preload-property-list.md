# 앱 시작 직후 로컬 DB에 저장된 매물 목록을 뒷단에서 미리 로딩하도록 구조 변경

## Context and Problem Statement

실기기에서 앱을 처음 키고 매물 탭에 처음 들어가면 딜레이가 발생.
매물 목록을 처음 불러올 때 백그라운드 isolate를 만들고 DB를 여는데 매물 탭이 생성될 때 DB에 처음 접근하기 때문에 딜레이가 발생했었음

## Decision Drivers

* 유저가 불편함을 답답함을 느끼지 않을 정도의 반응성을 고려함

## Considered Options

* 로딩 인디케이터를 추가하여 UI적으로 해결하기
* 스플래시에서 DB 호출이 완료된 후 메인 페이지 진입하기
* `runApp` 직후 뒷단에서 미리 불러오기

## Decision Outcome

선택: "`runApp` 직후 뒷단에서 미리 불러오기"
사유:  앱 시작은 그대로 두면서 사용자가 매물 탭을 누르기 전에 불러오기를 끝낼 수 있기 때문

`lib/main.dart`에서 `ProviderContainer`를 직접 만들어 `UncontrolledProviderScope`로 넘기고 `runApp` 직후 `_preloadPropertyList`에서 `propertyListVMProvider`를 읽음

### Consequences

* 장점: 매물 탭에 처음 들어갈 때 빈 화면 없이 바로 목록이 보임
* 단점: 매물 탭에 가지 않아도 앱 시작 때 DB를 호출함

  - 3회씩의 테스트로 적은 모수였기에 매물 수가 늘수록 빈 화면이 길어지거나 미리 불러오기가 늦어지는 경향을 파악하긴 어려움

#### 스플래시에서 DB 호출이 완료된 후 메인 페이지 진입하기

- 방법: 앱을 완전히 종료 → 재시작 → 스플래시 → 홈 첫 화면까지 걸린 시간을 매물 수별로 3회 측정
- 비교: 이전 버전(미리 불러오기 없음) / 스플래시 대기 버전
- 앱 코드 시작(`main()` 첫 줄) → 홈 첫 화면 시간을 로그로 확인, 값은 3회 평균, 괄호는 회차별 값

| 매물 수 | 이전 버전 | 스플래시 대기 버전 | 늘어난 시간 |
|---|---|---|---|
| 100개 | 571ms (572 / 624 / 516) | 794ms (870 / 914 / 597) | +223ms |
| 200개 | 540ms (494 / 647 / 479) | 945ms (821 / 996 / 1017) | +405ms |
| 300개 | 617ms (501 / 506 / 844) | 700ms (833 / 648 / 619) | +83ms |
| 400개 | 613ms (501 / 493 / 845) | 2,578ms (1083 / 1045 / 5607) | +1,965ms |

- 스플래시 대기 버전에서 매물 목록 로딩이 끝난 시점(`main()` 시작 기준): 100개 243~490ms, 200개 433~550ms, 300개 256~396ms, 400개 589~594ms (3회차 4,450ms)
- 결과
  - 스플래시 대기 버전은 매물 목록 로딩 시간만큼 홈 화면이 늦게 뜸 (대부분 약 0.1~0.5초)
  - 400개 3회차는 로딩이 4.45초 걸려 홈 화면이 5.6초 뒤에 뜸. 이 회차를 빼면 400개 평균은 1,064ms(+451ms)
  - 3회씩이라 매물 수에 따라 시간이 늘어나는 경향을 단정지을 수 없음. DB를 처음 여는 시간이 조회 시간보다 커서 매물 수 영향이 작은 것으로 보임


## Pros and Cons of the Options

### 로딩 인디케이터를 추가하여 UI적으로 해결하기

* 장점: 어떤 동작을 하는 중인지 유저가 직관적으로 이해하기 쉬움
* 단점: 매물 목록을 확인하기 위해 딜레이가 필요함. 스피너가 잠깐 보여질 때 끊기는 느낌이 들고, 스피너가 한 바퀴 도는데 드는 시간이 길어서 유저는 더 많은 시간을 기다려야 함.

### 스플래시에서 DB 호출이 완료된 후 메인 페이지 진입하기

* 장점: 매물 탭을 누를 때 항상 목록이 준비되어 있음
* 단점: 불러오는 시간만큼 앱 시작이 늦어짐
  - 3번의 테스트임에도 불구하고 1초를 넘기는 동작과 늘어난 초수가 5초가량 늘어난 케이스가 관찰되어 실 기기에서는 꽤 자주 관찰될 수 있을 것이라 판단됨

### `runApp` 직후 뒷단에서 미리 불러오기

* 장점: 앱 시작이 늦어지지 않음
* 단점: 앱을 켜자마자 매물 탭을 눌렀을 때 DB 호출이 완료되지 않은 경우 빈 화면이 보임
  - 홈 탭 진입 이후 0.3초 이내로 매물 탭으로 이동되었을 때 오히려 로딩이 더 늦어지는 경우가 있으나 실제 사용자의 동작에서 빠르게 탭을 전환하는 케이스는 적을 것이라 판단됨

## More Information

- 코드 위치: `lib/main.dart`의 `_preloadPropertyList`
- 홈 화면이 뜨고 0.2초 안에 매물 탭을 누르면 빈 화면이 남음 (Confirmation의 "앱을 켜자마자 매물 탭을 여는 경우" 참고)
- 시뮬레이터 디버그 빌드 수치라 실기기 릴리즈 빌드와 다를 수 있음
