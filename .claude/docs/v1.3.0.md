# 출시 체크리스트 (1.3.0)

1.3.0 배포 전에 처리할 일.

## 1. AI 글쓰기
- [ ] 사진 복사 시 HEIC 원본 확인 필요: 모바일 `Pasteboard.writeImage`에 HEIC bytes를 넣으면 붙여 넣는 앱이 못 읽을 수 있음 → 확인 후 필요하면 PNG로 변환 (`blog_repository_impl.dart`의 `_resizeToPng` 참고)
- [ ] Windows: `windows/runner/flutter_window.cpp`의 HTML 클립보드 채널 빌드(`/W4 /WX`) 확인, 본문 붙여넣기 시 네이버·노션 서식 적용 확인, 사진 복사(`Pasteboard.writeFiles`) 확인
- [ ] Android: 사진 복사(`Pasteboard.writeImage` + `FileProvider` 설정)와 이메일 문의(`mailto` queries) 실기기 동작 확인

## 2. 리팩터링
- [ ] `AppManager`의 설정(`settings`, `windowSideWidth`)을 Riverpod provider로 분리
  - `runApp` 전에 읽은 사이드 너비를 `imageDirectoryProvider`처럼 override로 초기값 주입
  - 사이드 너비 VM(`resize`·`save` Action)으로 매물 목록·매물 상세·지도 화면의 `ValueListenableBuilder` 교체, 드래그 중 다시 그리는 범위는 `Consumer`로 좁힘
  - `mapImagesReady`는 화면 상태가 아니라서 `AppManager`에 유지
- [ ] `lib/core/di/providers.dart`를 기능별 파일로 분리
  - 예: `database_providers.dart`, `network_providers.dart`(Dio), `property_providers.dart`, `address_providers.dart`, `blog_providers.dart`, `app_update_providers.dart`
  - `providers.dart`는 각 파일을 export만 해서 기존 import 유지
  - 저장소 provider에 `@visibleForTesting`을 붙여 화면에서는 UseCase provider만 쓰도록 제한 (테스트 override는 그대로 가능)
- [ ] VM의 UseCase 사용을 `SplashVM` 방식으로 통일
  - 클래스 맨 위(`build()` 위)에 `late final XxxUseCase _xxxUseCase = ref.read(xxxUseCaseProvider);`로 선언하고, 메서드 안의 `ref.read(xxxUseCaseProvider)`를 필드 호출로 교체
  - 대상: `apply_property_address_vm.dart`, `apply_property_extra_vm.dart`, `edit_property_address_vm.dart`, `edit_property_vm.dart`, `map_vm.dart`, `property_detail_vm.dart`, `property_list_vm.dart`, `property_write_vm.dart`
  - `ui_patterns.md` 5장(상태·VM 패턴)에 규칙 추가
- [ ] `AppConfig.supportEmail`을 env.json으로 이동
  - `String.fromEnvironment('SUPPORT_EMAIL')`로 읽기 (`windowsUpdateUrl`과 같은 방식)
  - `tool/build.dart` `requiredKeys`에 `SUPPORT_EMAIL` 추가, `CLAUDE.md` env.json 키 안내 갱신
  - 사용처: `property_write_vm.dart` 오류 문의 메일(`mailto`)
  - 앱 바이너리에는 그대로 들어감 (저장소 노출만 막음)
